# Docker Architecture & Flow Diagram

## ?? What is Docker?

Docker packages your application and all its dependencies into a **container** - a lightweight, standalone, executable package that includes:
- Your .NET application
- .NET runtime
- Operating system libraries
- All dependencies

Think of it like a shipping container for software!

## ?? Layer Caching Explanation

```
First Build (Full):
??????????????????????????????
? Layer 1: FROM sdk:10.0     ? ? Downloaded & cached
??????????????????????????????
? Layer 2: WORKDIR /src      ? ? Created & cached
??????????????????????????????
? Layer 3: COPY .csproj      ? ? Created & cached
??????????????????????????????
? Layer 4: RUN restore       ? ? Downloaded packages & cached
??????????????????????????????
? Layer 5: COPY . .          ? ? Source code & cached
??????????????????????????????
? Layer 6: RUN build         ? ? Compiled & cached
??????????????????????????????
            ?
         BUILD IMAGE

Second Build (After code change):
??????????????????????????????
? Layer 1: FROM sdk:10.0     ? ? Use cached (no change)
??????????????????????????????
? Layer 2: WORKDIR /src      ? ? Use cached (no change)
??????????????????????????????
? Layer 3: COPY .csproj      ? ? Use cached (no change)
??????????????????????????????
? Layer 4: RUN restore       ? ? Use cached (no change)
??????????????????????????????
? Layer 5: COPY . .          ? ? Rebuild (code changed!)
??????????????????????????????
? Layer 6: RUN build         ? ? Rebuild (source changed)
??????????????????????????????
            ?
    Faster build! Only layers 5-6 rebuilt
```

This is why we copy `.csproj` separately before `COPY . .`!

## ?? Key Docker Concepts

```
IMAGE: Blueprint (like a .exe file)
  - Read-only template
  - Contains app + dependencies + OS libs
  - Created by Dockerfile

CONTAINER: Running instance of image
  - Isolated process
  - Own filesystem
  - Own network
  - Own environment variables

LAYER: Intermediate result of Dockerfile instruction
  - Cached for faster rebuilds
  - Each RUN/COPY creates a layer

REGISTRY: Repository of Docker images
  - Docker Hub (public)
  - Azure Container Registry (private)
  - Self-hosted registry

DOCKER ENGINE: Runtime that executes containers
  - Isolates processes
  - Manages resources
  - Handles networking
```
